# N-Queens 五架构公共基线（精简版）

> 适用于本组 5 种架构实现：Pipe-Filter、Call/Return（迭代）、Call/Return（回溯）、Blackboard、MapReduce。  
> 核心原则：**五种方案使用同一套 N 皇后问题定义、搜索规则和剪枝规则，只改变架构组织方式。**

---

## 1. 统一任务目标

- 统一求 **N 皇后首个解**。
- 统一实验脚本固定测试：
  - `N = 8`
  - `N = 10`
  - `N = 12`
- 输入统一由公共 CLI / 实验脚本传入 `--n`。
- 五种实现最终必须得到相同的 `columns` 首解数组。

按 `row: 0 → N-1`、`col: 0 → N-1` 的顺序搜索时，标准首解可用于自检：

| N | 首解 columns（零基列下标） |
|---:|---|
| 8 | `[0, 4, 7, 5, 2, 6, 1, 3]` |
| 10 | `[0, 2, 5, 7, 9, 4, 8, 1, 3, 6]` |
| 12 | `[0, 2, 4, 7, 9, 11, 5, 10, 1, 6, 8, 3]` |

---

## 2. N 皇后规则

在 `N × N` 棋盘上放置 `N` 个皇后，使任意两个皇后：

- 不在同一行；
- 不在同一列；
- 不在同一条对角线。

本组统一采用 **逐行放置**：

```text
row = 0 → 1 → 2 → ... → N-1
```

每一行只放一个皇后，因此不需要额外检查同行冲突。

---

## 3. 统一搜索规则

### 3.1 搜索空间

一个状态表示：

> 前 `row` 行已经合法放置完成，现在准备处理第 `row` 行。

例如：

```text
queens = [1, 3, 0]
row = 3
```

表示：

```text
第0行 → 第1列
第1行 → 第3列
第2行 → 第0列
```

接下来处理第 3 行。

### 3.2 候选顺序

所有方案统一：

```text
row：0 → N-1
col：0 → N-1
```

即每一行都从左到右尝试所有列。

不使用：

- 随机顺序；
- 中间优先；
- 启发式列排序。

---

## 4. 统一合法性判断

对于候选位置：

```text
(row, col)
```

只检查以下三项。

### 列冲突

```text
col
```

对应列必须未被占用。

### 主对角线

统一索引：

```text
row - col + N - 1
```

### 副对角线

统一索引：

```text
row + col
```

只有同时满足：

```text
列未占用
AND
主对角线未占用
AND
副对角线未占用
```

当前候选才合法。

否则立即剪枝。

---

## 5. 统一剪枝与状态表示

五种架构统一采用三个等价位向量：

```text
columnsMask
diag1Mask
diag2Mask
```

推荐使用：

```java
long
```

统一逻辑状态可抽象为：

```text
NQueenState
├── row
├── queens[]
├── columnsMask
├── diag1Mask
└── diag2Mask
```

其中：

- `row`：下一步处理的行；
- `queens[]`：记录各行皇后所在列；
- 三个 Mask：用于快速判断列和两条对角线是否冲突。

---

## 6. 五种方案共同的核心算法

```text
当前 Partial State
        │
        ▼
枚举当前行 col = 0 ... N-1
        │
        ▼
检查列 / 两条对角线
      /     \
   冲突     合法
    │        │
  Prune   New State
             │
       ┌─────┴─────┐
       │           │
    row < N      row == N
       │           │
    Continue     Solution
```

逻辑上：

1. 当前处理第 `row` 行；
2. 从 `col=0` 到 `N-1` 枚举候选；
3. 使用三个 Mask 判断冲突；
4. 冲突则立即剪枝；
5. 合法则产生下一状态；
6. 放满 N 行后记为一个完整解；
7. 五种架构统一返回按上述顺序遇到的第一个完整解。

---

## 7. 统一禁止的额外优化

为了保证跨架构比较公平，未经全组讨论不得加入：

- 对称性剪枝；
- 第一行只搜索一半；
- 镜像解推导；
- 启发式排序；
- 随机搜索；
- Memoization / 状态缓存；
- 针对特定 N 的特殊优化；
- 其他额外剪枝。

如果需要修改公共算法规则，必须先由四人共同确认。

---

## 8. 五种架构允许不同的地方

统一的是：

- 问题；
- 搜索空间；
- 候选顺序；
- 合法性判断；
- 剪枝规则。

允许不同的是：

- 组件划分；
- 连接器；
- 数据如何传递；
- 状态如何保存；
- 控制流；
- 调度机制。

具体表现为：

- **Pipe-Filter**：通过 Pipe / Queue 传递 State；
- **Call/Return Iterative**：在求解层内使用迭代方式；
- **Call/Return Backtracking**：在求解层内使用递归回溯；
- **Blackboard**：通过 Blackboard + Knowledge Sources + Controller 协作；
- **MapReduce**：通过 Map → Shuffle → Reduce 组织搜索过程。

## 9. 统一输入、输出与实验规范

### 输入

统一由公共 CLI / 实验脚本传入 `--n`，例如调试运行：

```powershell
.\scripts\run.ps1 -Architecture mapreduce -N 8
```

正式实验由脚本固定运行 `N=8/10/12`。

### 输出

公共 CLI 统一输出一行 JSON，至少包含：

```text
N
mode = first
status
columns
solve_elapsed_ns
```

正式性能实验不要打印棋盘图或大量中间状态。

### 实验环境

最终比较时统一：

- 同一台机器；
- 同一种编程语言；
- 同一语言/编译器版本；
- 同一编译参数；
- 同一运行次数；
- 同一计时范围。

推荐只统计核心求解时间，不把验证、打印和 JVM 启动计入。

- [ ] `col: 0 → N-1`

- [ ] 输出首解 `columns`

## 一句话总结

> **五种架构解决同一个 N-Queens 首解问题，采用完全一致的搜索空间、候选顺序、合法性判断和位向量剪枝规则；只有组件组织、数据流、控制流和通信方式可以因架构风格而不同。**
